# Glossar

Englische Leitbegriffe ermöglichen eindeutige Dateinamen und Verweise. Unterricht, Gespräche und fachliche Texte dürfen deutsch bleiben.

| Begriff | Bedeutung und Abgrenzung |
| --- | --- |
| Solution | Gesamtlösung des Prototyps: durchgängiger Geschäftsprozess mit mehreren Systemen |
| Prototype Brief | Gemeinsamer Prototyp-Auftrag; tatsächlicher Bauumfang und E2E-Szenarien. Kein zweites Soll-Konzept |
| Solution Architecture | Gesamtlösungsarchitektur: Systemgrenzen und Zusammenspiel |
| System | Anwendung oder Mock mit eigenem Auftrag und Repository; nicht automatisch eine Person |
| System PRD | Product Requirements Document: fachliche Anforderungen, Prioritäten, Akzeptanzkriterien und Systemtests |
| System Architecture | Technischer Aufbau innerhalb eines Systems, mit verständlichem Überblick |
| Component | Technischer Baustein innerhalb eines Systems. Kein Synonym für System oder persönliche Verantwortung |
| Feature | Fachlich sinnvoll abgrenzbare, prüfbare Fähigkeit; genau eine hauptverantwortliche Person |
| Feature Plan | Umsetzungs- und Prüfgrundlage für ein Feature; technische Tasks plant der Agent |
| Design Brief | Gestaltungsgrundsätze und repräsentative Referenzen; kein vollständiger Maskenkatalog |
| Interface Contract | Schnittstellenvertrag: Operationen, Nachrichten, Fehler, Aufruf- und Versionsregeln |
| Data Contract | Datenvertrag: fachliche Bedeutung, Formate, IDs, Einheiten, Werte und Konsistenzregeln |
| Acceptance Criteria | Akzeptanzkriterien: Bedingungen, unter denen das Feature seinen Zweck erfüllt |
| Test Scenario | Testszenario: Ausgangslage, Daten, Aktionen und erwartete Ergebnisse |
| Validation | Ausgeführte Prüfung anhand vereinbarter Kriterien; ersetzt die menschliche Abnahme nicht |
| Acceptance | Fachliche Abnahme durch die verantwortliche Person |
| Issue / Ticket | Konkreter Arbeitsauftrag mit Verantwortung, Verweisen, Diskussion und Status |
| Epic | Grössere fachliche Initiative; hier keine zusätzliche Pflichtkategorie und nicht gleich Milestone |
| Milestone | Geplante Ausbaustufe in einem Repository, bündelt Issues |
| Release | Nachvollziehbarer veröffentlichter Stand; im E2E-Kontext ein geprüfter Verbund konkreter Versionen |
| Branch / Worktree | Getrennte Änderungslinie / separates Arbeitsverzeichnis für parallele Arbeit |
| Pull Request | Optionaler Vorschlag zur Zusammenführung; keine Pflicht zum menschlichen Code-Review |
| Skill | Wiederverwendbare Anleitung mit gegebenenfalls Vorlagen und Hilfsprogrammen; kein eigener Agent |
| Mock / Mockup | Ein Mock simuliert benötigtes Systemverhalten; ein visueller Mockup hilft, Anforderungen zu erkunden |

PIV bedeutet Plan–Implement–Validate. Diese drei Schritte werden iterativ ausgeführt; sie sind keine einmalige vollständige Vorabplanung des gesamten Systems.
